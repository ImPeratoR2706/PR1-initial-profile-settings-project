====================================================================
ЧАСТЬ 1. КАК ЗАПУСТИТЬ ПРОЕКТ
====================================================================

Структура проекта:

profile_settings/
├── README.md
├── requirements.txt
├── main.py
├── profiles.py
├── settings.py
├── parameters.py
├── storage.py
├── utils.py
├── data/
│   ├── profiles.json
│   ├── settings.json
│   └── parameters.json
└── tests/
    ├── test_profiles.py
    ├── test_settings.py
    └── test_parameters.py

1) Открыть папку проекта в VS Code (File → Open Folder...).

2) Открыть терминал в VS Code (Ctrl+`) и создать виртуальное окружение
   (если оно ещё не создано):

   Windows (PowerShell):
       python -m venv .venv

   macOS / Linux:
       python3 -m venv .venv

3) Активировать виртуальное окружение:

   Windows (PowerShell):
       .venv\Scripts\Activate.ps1

   macOS / Linux:
       source .venv/bin/activate

   Если Windows пишет ошибку про "запрет выполнения скриптов"
   (execution policy), один раз выполнить (в этом же PowerShell,
   от имени текущего пользователя):
       Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
   и повторить активацию.

   Признак успешной активации — слева в строке терминала появляется
   приписка (.venv).

4) Установить зависимости проекта:

       pip install -r requirements.txt

5) Запустить приложение:

       python main.py

   Появится главное меню:

       1. Показать профили
       2. Найти профиль по названию
       3. Показать настройки профиля
       4. Показать параметры настройки
       5. Добавить профиль
       6. Добавить настройку
       7. Добавить параметр
       8. Изменить значение параметра
       9. Сбросить параметр к значению по умолчанию
       10. Показать параметры по типу
       11. Проверить значение параметра (без изменения)
       0. Выход

6) Чтобы выйти из виртуального окружения после работы:

       deactivate


====================================================================
ЧАСТЬ 2. ПРОВЕРКА ПРОЕКТА ПЕРЕД СДАЧЕЙ
====================================================================

Выполнять из активированного виртуального окружения (см. выше).

1) Автоматические тесты (должно быть "13 passed"):

       pytest -v

2) Проверка стиля кода PEP 8 (должно завершиться без вывода ошибок,
   код возврата 0):

       flake8 .

   Если Windows не находит команду flake8 ("Имя "flake8" не
   распознано..."):
   - убедиться, что виртуальное окружение активировано (шаг 3 выше);
   - убедиться, что зависимости установлены (шаг 4 выше);
   - как запасной вариант можно вызвать через модуль python:
         python -m flake8 .
         python -m pytest -v

3) Проверить состояние Git (все изменения должны быть закоммичены
   и отправлены на GitHub):

       git status
       git log --oneline

   В истории должны быть видны как минимум коммиты:
       ... first commit
       ... PR2: функциональная модель на коллекциях

--------------------------------------------------------------
1. Порядок демонстрации
--------------------------------------------------------------

1. Кратко назвать тему индивидуального проекта: «Система настройки
   пользовательских профилей». Сущности: профиль, настройка,
   параметр. Профиль объединяет настройки (категории, например
   «Внешний вид», «Уведомления»), настройка содержит параметры —
   именованные значения с проверкой допустимости (тип, диапазон,
   список допустимых значений).

2. Показать структуру проекта в VS Code (Explorer): main.py,
   profiles.py, settings.py, parameters.py, storage.py, utils.py,
   data/, tests/.

3. Запустить приложение и продемонстрировать сценарии вживую
   (см. сценарий ниже).

4. Показать автоматические тесты и проверку стиля кода (pytest,
   flake8).

5. Показать историю коммитов в Git.

6. Ответить на контрольные вопросы преподавателя.

--------------------------------------------------------------
2. Сценарий живой демонстрации (что вводить в меню)
--------------------------------------------------------------

Запустить: python main.py

Далее по шагам:

  Выбор "1"  → показать список профилей (демонстрирует
               show_profiles + sort_profiles).

  Выбор "5"  → добавить новый профиль (ввести название, владельца,
               описание) — показывает функцию add_profile и
               сохранение записи в коллекции.

  Выбор "6"  → добавить настройку для существующего профиля (ID
               профиля, категория) — функция add_setting.

  Выбор "7"  → добавить параметр для настройки: указать ID
               настройки, ключ (например font_size), тип (int),
               значение (14), значение по умолчанию (12), min (10),
               max (24) — функция add_parameter.

  Выбор "8"  → изменить значение параметра: сначала ввести
               заведомо недопустимое значение (например 100 при
               max=24) — показать сообщение «Недопустимое значение
               параметра»; затем ввести допустимое значение
               (например 20) — показать «Значение параметра
               допустимо» и «Значение сохранено». Это демонстрирует
               validate_parameter_value и update_parameter_value.

  Выбор "11" → проверить значение параметра без изменения
               (check_parameter_value) — показать, что значение
               параметра при этом не меняется.

  Выбор "9"  → сбросить параметр к значению по умолчанию
               (reset_parameter_to_default).

  Выбор "10" → показать параметры по типу (например "int") —
               демонстрирует filter_parameters_by_type (генератор,
               yield) в сочетании с sort_parameters_by_key
               (сортировка через lambda).

  Выбор "0"  → выход с сохранением данных в JSON (data/*.json) —
               показать, что данные сохраняются между запусками.

--------------------------------------------------------------
4. Краткие ответы на типовые контрольные вопросы
--------------------------------------------------------------

Q: Почему используются коллекции словарей, а не классы?
A: На данном этапе (ПР2) задача — научиться работать с коллекциями
   (списками словарей), функциями и их комбинациями без ООП.
   Переход к классам выполняется позже, на ПР3.

Q: Как организовано хранение данных?
A: Три JSON-файла (data/profiles.json, data/settings.json,
   data/parameters.json). Загрузка/сохранение инкапсулированы в
   storage.py, ошибки чтения (FileNotFoundError,
   json.JSONDecodeError) обрабатываются через try/except — при
   отсутствии файла возвращается пустой список.

Q: Как проверяется допустимость значения параметра?
A: Функция validate_parameter_value проверяет соответствие типу
   (str/int/bool) и, если задано, диапазону (min_value/max_value)
   или списку допустимых значений (allowed_values). Функция
   check_parameter_value объединяет поиск параметра по ключу и эту
   проверку в одном вызове, не изменяя сам параметр.

Q: Что такое генератор и где он используется?
A: Функция filter_parameters_by_type реализована через yield —
   она отдаёт подходящие параметры по одному, по мере обхода
   коллекции, не создавая промежуточный список в памяти.

Q: Где используются lambda-функции?
A: В sort_parameters_by_key и sort_profiles — сортировка списка
   словарей по значению конкретного ключа через
   sorted(..., key=lambda x: x["..."]).

Q: Как обрабатываются исключения?
A: Например, update_parameter_value выбрасывает KeyError, если
   параметр с указанным ключом не найден в данной настройке; вызов
   в main.py оборачивается в try/except KeyError для корректного
   вывода сообщения пользователю без падения программы.

Q: Как проверялось качество кода?
A: flake8 — соответствие PEP 8 (длина строк, форматирование,
   неиспользуемые импорты). pytest — 13 автотестов, проверяющих
   добавление, поиск, сортировку, валидацию, изменение и сброс
   значений параметров, настроек и профилей.

Q: Как ведётся версионирование?
A: Git-репозиторий с коммитами по этапам работы (первый коммит —
   стартовая версия ПР1, второй — "PR2: функциональная модель на
   коллекциях"), с отправкой на удалённый репозиторий GitHub
   (origin).
