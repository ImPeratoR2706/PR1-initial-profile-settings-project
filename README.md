# Система настройки пользовательских профилей

Консольное приложение для управления профилями пользователей, их
настройками и параметрами. Реализовано на основе объектной модели
предметной области.

## Назначение

Roomly-подобное приложение (по аналогии со сквозным примером
методических указаний), но для другой предметной области: пользователь
создаёт один или несколько профилей, каждый профиль объединяет
настройки по категориям, а каждая настройка содержит параметры —
именованные значения с проверкой допустимости.

## Целевая аудитория

Пользователи веб- и десктоп-приложений, которым требуется гибко
настраивать внешний вид, уведомления и параметры приватности под себя,
а также администраторы, задающие значения настроек по умолчанию.

## Предметная область

Основными объектами предметной области являются:

- пользователь;
- профиль;
- настройка;
- параметр.

Пользователь может создавать несколько профилей. Каждый профиль
объединяет несколько настроек (категорий). Каждая настройка содержит
несколько параметров, значения которых проверяются на допустимость по
типу, диапазону или списку допустимых значений.

## Основные сущности

### User — пользователь
Объект `User` представляет пользователя системы.

Основные атрибуты:
- `id` — уникальный идентификатор пользователя;
- `username` — имя пользователя;
- `email` — адрес электронной почты.

Основные методы:
- `__str__()` — строковое представление пользователя;
- `from_data()` — создание объекта `User` из набора данных
  (`@classmethod`).

### Profile — профиль
Объект `Profile` представляет именованный набор настроек пользователя.

Основные атрибуты:
- `id` — уникальный идентификатор профиля;
- `user` — объект `User`, которому принадлежит профиль;
- `name` — название профиля;
- `description` — описание профиля;
- `settings` — список объектов `Setting`, относящихся к профилю.

Основные методы:
- `add_setting()` — добавить настройку в профиль;
- `find_setting()` — найти настройку профиля по категории;
- `__str__()` — строковое представление профиля.

### Setting — настройка
Объект `Setting` представляет категорию параметров профиля (например,
«Внешний вид», «Уведомления»).

Основные атрибуты:
- `id` — уникальный идентификатор настройки;
- `profile` — объект `Profile`, которому принадлежит настройка;
- `category` — название категории;
- `parameters` — список объектов `Parameter`, относящихся к настройке.

Основные методы:
- `add_parameter()` — добавить параметр в настройку;
- `find_parameter()` — найти параметр настройки по ключу;
- `__str__()` — строковое представление настройки.

### Parameter — параметр
Объект `Parameter` представляет именованное значение настройки с
проверкой допустимости.

Основные атрибуты:
- `id` — уникальный идентификатор параметра;
- `setting` — объект `Setting`, которому принадлежит параметр;
- `key` — ключ параметра;
- `value` — текущее значение;
- `value_type` — тип значения (`str`, `int`, `bool`);
- `default_value` — значение по умолчанию;
- `min_value`, `max_value` — допустимый диапазон (для типа `int`);
- `allowed_values` — список допустимых значений (для типа `str`).

Основные методы:
- `is_valid_value()` — проверить допустимость значения;
- `update_value()` — изменить значение параметра;
- `reset_to_default()` — сбросить параметр к значению по умолчанию;
- `__str__()` — строковое представление параметра;
- `validate_type()` — проверить соответствие значения базовому типу
  (`@staticmethod`).

## Взаимодействие объектов

```text
User
 └── создаёт ──> Profile
                   └── содержит ──> Setting
                                      └── содержит ──> Parameter
```

Каждый дочерний объект хранит ссылку на родительский: `Profile.user`,
`Setting.profile`, `Parameter.setting`. Это позволяет обращаться к
данным связанных объектов напрямую, например `parameter.setting.category`
или `profile.user.username`.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

- `data/users.json`;
- `data/profiles.json`;
- `data/settings.json`;
- `data/parameters.json`.

При загрузке данные из JSON преобразуются в объекты `User`, `Profile`,
`Setting` и `Parameter` с восстановлением связей между ними. При
сохранении объекты преобразуются обратно в данные JSON: связи с
родительскими объектами записываются в виде идентификаторов
(`user_id`, `profile_id`, `setting_id`).

## Назначение модулей

### `main.py`
Точка входа в приложение. Отвечает за запуск приложения, отображение
меню, получение данных от пользователя и организацию пользовательских
сценариев.

### `models/users.py`
Содержит класс `User`.

### `models/profiles.py`
Содержит класс `Profile`.

### `models/settings.py`
Содержит класс `Setting`.

### `models/parameters.py`
Содержит класс `Parameter`.

### `storage.py`
Отвечает за загрузку и сохранение данных. Выполняет преобразование:
- JSON → объекты Python;
- объекты Python → JSON.

### `utils.py`
Содержит вспомогательные функции безопасного ввода (`input_int()`,
`input_choice()`) и демонстрационный декоратор `log_call()`.

### `tests/`
Содержит автоматизированные тесты классов проекта.

## Запуск приложения

```text
python main.py
```

После запуска отображается главное меню.

## Тестирование

Для запуска автоматизированных тестов выполнить:

```text
pytest -v
```

Тесты проверяют:
- создание и работу объектов `User`, `Profile`, `Setting`, `Parameter`;
- методы классов;
- связь настройки с профилем и параметра с настройкой;
- проверку допустимости и изменение значения параметра;
- сброс параметра к значению по умолчанию.

## Проверка качества кода
