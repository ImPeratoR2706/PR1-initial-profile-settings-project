# Система настройки пользовательских профилей

## Назначение

Приложение для управления профилями пользователей, их настройками и
параметрами. Консольная версия приложения (ПР1-ПР3) дополнена
веб-интерфейсом на Django (ПР5).

Приложение позволяет:
- просматривать профили пользователей в браузере;
- просматривать информацию об отдельном профиле и его настройках;
- просматривать список настроек в браузере;
- просматривать информацию об отдельной настройке и её параметрах;
- находить профили и настройки по идентификатору, заданному в адресе
  страницы;
- хранить данные между запусками приложения.

## Используемые технологии

- Python 3;
- Django 5.2 — веб-фреймворк;
- HTML — разметка веб-страниц;
- CSS и Bootstrap 5.3 — оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Пользователи веб- и десктоп-приложений, которым требуется гибко
настраивать внешний вид, уведомления и параметры приватности под себя,
а также администраторы, задающие значения настроек по умолчанию.

## Предметная область

Основные сущности проекта: пользователь, профиль, настройка, параметр.
Пользователь создаёт один или несколько профилей. Каждый профиль
объединяет несколько настроек (категорий, например «Внешний вид» или
«Уведомления»). Каждая настройка содержит несколько параметров —
именованных значений с проверкой допустимости по типу, диапазону или
списку допустимых значений.

Для предметной области реализованы собственные Python-классы (пакет
`models/`, см. ПР3). На текущем этапе (ПР5) данные по-прежнему хранятся
в JSON-файлах каталога `data/`. Django ORM и база данных пока не
используются.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3). Отвечает за запуск
консольного приложения, отображение меню и организацию
пользовательских сценариев.

### `profile_settings_site/`
Пакет настроек Django-проекта: `settings.py` — настройки проекта,
`urls.py` — маршрутизация верхнего уровня, `asgi.py`/`wsgi.py` — точки
взаимодействия с сервером.

### `homepage/`
Django-приложение, отвечающее за главную страницу: `views.py`
содержит вспомогательную функцию `page()` (общий HTML-каркас: Bootstrap
и навигация) и view-функции `index()`, `page_not_found()`; `urls.py` —
маршрут главной страницы. Функция `page()` размещена здесь, так как
главная страница задаёт общий вид всех остальных страниц — остальные
приложения импортируют её.

### `profiles/`
Django-приложение, отвечающее за профили: `views.py` — view-функции
`profile_list()` и `profile_detail()`; `urls.py` — маршруты
приложения; `models.py` — Django-модели (заполняется на следующих
практических работах).

### `settings/`
Django-приложение, отвечающее за настройки профилей: `views.py` —
view-функции `setting_list()` и `setting_detail()`; `urls.py` —
маршруты приложения.

### `models/`
Классы предметной области и функции работы с ними (пакет ПР3):
`users.py` — класс `User`, `profiles.py` — класс `Profile` и функции
работы с профилями, `settings.py` — класс `Setting`, `parameters.py` —
класс `Parameter`.

### `storage.py`
Отвечает за загрузку и сохранение данных. Выполняет преобразование
JSON → объекты Python и обратно.

### `utils.py`
Содержит вспомогательные функции консольного ввода и демонстрационный
декоратор `log_call()`.

### `tests/`
Содержит автоматизированные тесты классов предметной области.

## Страницы веб-интерфейса

| Страница | URL | View-функция |
|---|---|---|
| Главная | `/` | `homepage.views.index()` |
| Список профилей | `/profiles/` | `profiles.views.profile_list()` |
| Страница профиля | `/profiles/<int:profile_id>/` | `profiles.views.profile_detail()` |
| Список настроек | `/settings/` | `settings.views.setting_list()` |
| Страница настройки | `/settings/<int:setting_id>/` | `settings.views.setting_detail()` |

Если профиль или настройка с указанным идентификатором не найдены,
соответствующая страница возвращает код статуса 404. Несуществующий
адрес обрабатывается общим обработчиком `homepage.views.page_not_found`.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

- просмотр списка профилей;
- просмотр информации о профиле и его настройках;
- просмотр списка настроек;
- просмотр информации о настройке и её параметрах.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии. В
веб-интерфейсе они появятся, когда будут добавлены формы и
POST-запросы:

- добавление профиля, настройки, параметра;
- изменение значения параметра;
- сброс параметра к значению по умолчанию.

## Запуск приложения

Веб-версия (Django):

```text
python manage.py runserver
```

После запуска открыть в браузере адрес:

```text
http://127.0.0.1:8000/
```

Консольная версия (сохранена):

```text
python main.py
```
